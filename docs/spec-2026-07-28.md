# MCP 2026-07-28: wire shapes used here

Compiled from https://modelcontextprotocol.io/specification/2026-07-28/ (changelog, basic/index, basic/versioning, basic/patterns/mrtr, basic/transports/streamable-http, server/discover, server/tools, schema). Last checked 2026-11-11.

Entries marked _(unconfirmed)_ have not been checked against the schema text itself. Not covered: the lifecycle page, the caching utilities page and the stdio transport.

## Every client request

`params._meta` must carry:

| Key                                                                    | Required                       |
| ---------------------------------------------------------------------- | ------------------------------ |
| `io.modelcontextprotocol/protocolVersion` (e.g. `"2026-07-28"`)        | Yes                            |
| `io.modelcontextprotocol/clientCapabilities` (object; `{}` means none) | Yes                            |
| `io.modelcontextprotocol/clientInfo` (`{name, version}`)               | SHOULD; optional in the schema |

A request missing a required field is rejected with `-32602`, HTTP 400.

## HTTP headers (Streamable HTTP, POST only)

- `MCP-Protocol-Version`: required on every POST; must equal the `_meta` protocol version, otherwise HTTP 400 with `-32020` (HeaderMismatch).
- `Mcp-Method`: required on all requests; mirrors the body `method`.
- `Mcp-Name`: required on `tools/call`, `resources/read` and `prompts/get`; mirrors `params.name` or `params.uri`.
- The client's `Accept` lists both `application/json` and `text/event-stream`; the server replies with either.
- The body is a single JSON-RPC request or notification.
- A header that disagrees with the body, or a missing required header, is HTTP 400 with `-32020`.
- Notifications are acknowledged with `202` and no body. `GET` and `DELETE` on the endpoint return `405`. `Mcp-Session-Id` and `Last-Event-ID` are removed and ignored. An unknown method returns `404` with `-32601`.
- Servers MUST validate the `Origin` header and answer an invalid one with HTTP 403. A server that runs locally SHOULD bind to `127.0.0.1` only. Both rules guard against DNS rebinding.

## Error codes

Standard JSON-RPC: `-32700` parse error, `-32600` invalid request, `-32601` method not found, `-32602` invalid params, `-32603` internal error.

MCP-defined (`-32020` to `-32099` is reserved): `-32020` HeaderMismatch (400), `-32021` MissingRequiredClientCapability (400, with `data.requiredCapabilities`), `-32022` UnsupportedProtocolVersion (400):

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32022,
    "message": "Unsupported protocol version",
    "data": { "supported": ["2026-07-28", "2025-11-25"], "requested": "1900-01-01" }
  }
}
```

The specification does not state an HTTP status for `-32700` and `-32600`; this project uses 400.

## server/discover

Servers must implement it; clients may call it.

```json
{
  "jsonrpc": "2.0",
  "id": "discover-1",
  "result": {
    "resultType": "complete",
    "supportedVersions": ["2026-07-28"],
    "capabilities": { "tools": {}, "resources": {} },
    "_meta": {
      "io.modelcontextprotocol/serverInfo": { "name": "ExampleServer", "version": "1.0.0" }
    },
    "instructions": "...",
    "ttlMs": 3600000,
    "cacheScope": "public"
  }
}
```

## Tools

- `tools/list` result _(unconfirmed)_: `resultType`, `tools`, `nextCursor?`, `ttlMs`, `cacheScope`.
- `tools/call` result _(unconfirmed)_: `resultType`, `content`, `structuredContent?`, `isError?` (default false). A tool failure uses `isError: true` inside the result; a protocol failure uses a JSON-RPC error (an unknown tool is `-32602`).

## Multi round-trip requests (`tools/call`, `resources/read`, `prompts/get` only)

The server asks for input:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "input_required",
    "inputRequests": {
      "github_login": {
        "method": "elicitation/create",
        "params": {
          "mode": "form",
          "message": "Please provide your GitHub username",
          "requestedSchema": {
            "type": "object",
            "properties": { "name": { "type": "string" } },
            "required": ["name"]
          }
        }
      }
    },
    "requestState": "AEAD-protected blob"
  }
}
```

The client retries with a new request id, carrying `inputResponses` and `requestState` directly in `params` next to `name` and `arguments` (and `_meta`):

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "get_weather",
    "arguments": { "location": "New York" },
    "inputResponses": { "github_login": { "action": "accept", "content": { "name": "octocat" } } },
    "requestState": "eyJ..."
  }
}
```

At least one of `inputRequests` and `requestState` must be present. A server must not request a capability the client has not declared. `requestState` is attacker-controlled: protect its integrity (HMAC or AEAD) if it affects logic or authorization.

## Removed in this revision

- `initialize` and `notifications/initialized`. The specification says a modern-only server SHOULD name its supported versions in any error it returns to an `initialize` request.
- `ping`, `logging/setLevel` and `notifications/roots/list_changed`.
- Sessions (`Mcp-Session-Id`) and SSE resumability (`Last-Event-ID`).
- The standalone `GET` stream, `resources/subscribe` and `resources/unsubscribe`. `subscriptions/listen` over POST replaces them.
